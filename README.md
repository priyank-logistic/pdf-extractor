# Direct PDF-to-model experiment

This folder is an isolated alternative to the existing `src/pdf_to_json` pipeline.
It does not modify or call the existing extraction pipeline.

Flow:

```text
PDF -> render pages -> readable overlapping panels -> Gemma per page -> merge flat rows -> schema 3.0 JSON
```

It intentionally does not use `pdftotext`, coordinate reconstruction, static
vendor rules, or hierarchy repair passes. Each page is processed independently
to prevent large JSON responses from being truncated, then its flat rows are
combined in page order.

The output uses `data.tables` as its only row representation. Different printed
header layouts remain separate tables instead of being combined into one large
union, and rows are never duplicated in a second compatibility view. It does
not force varying PDF headers into fixed keys such as `cut_rate` or `rrp`, and
it repeats vertically merged values on every row they cover:

```json
{
  "headers": ["COLLETION", "DESIGN-SHADE", "ROLL RATE", "CUT RATE"],
  "rows": [
    {
      "COLLETION": "SALISTER",
      "DESIGN-SHADE": "6388",
      "ROLL RATE": "324 +5%",
      "CUT RATE": "360 +5%"
    },
    {
      "COLLETION": "SALISTER",
      "DESIGN-SHADE": "6399",
      "ROLL RATE": "324 +5%",
      "CUT RATE": "360 +5%"
    }
  ]
}
```

To migrate JSON generated by an older version without calling the model again:

```bash
python3 direct_model_extractor/migrate_outputs.py
```

If a printed header such as COLLECTION spans two physical columns and the
second column has no header of its own, the unnamed second column is called
`quality`. If it has a printed header such as DESIGN-SHADE, that printed header
is retained.

## Run

From the repository root:

```bash
python3 direct_model_extractor/extract.py \
  "KRISH CURTAIN NEW COLLECTION.pdf" \
  --output "direct_model_extractor/output/KRISH CURTAIN NEW COLLECTION.json" \
  --overwrite
```

The defaults are:

- Ollama URL: `http://192.168.0.254:11434`
- Model: `gemma4:12b`
- Timeout: 600 seconds
- Render resolution: 220 DPI
- Three overlapping vertical panels per page (use `--panels 1` to disable)
- 65,536-token context and 20,000-token output allowance for larger price lists
- One automatic retry when the model returns malformed JSON
- One page per model request by default (`--pages-per-request` can change this)
- Automatic panel-by-panel fallback when one dense page still produces oversized JSON

For a known dense page, add `--panel-requests` to skip the initial whole-page
attempt and send the visual panels separately immediately.

They can be overridden with CLI flags or `OLLAMA_URL`, `OLLAMA_MODEL`, and
`OLLAMA_TIMEOUT` environment variables.

## Important

This experiment is intentionally simple. Valid JSON does not prove that every
PDF row was read correctly. The output metrics report the number of returned
catalog/quality rows, but there is no independent source-row count because that
would require a second extraction mechanism.
